# Администрирование ATRAG

Админка встроена в Streamlit: после Google-входа администратор видит
переключатель «Чат / Админка», затем страницы Users и Documents.

## Настройка

В `.env` задайте подтверждённые Google email через запятую:

```dotenv
ATRAG_ADMIN_EMAILS=admin@example.com,second@example.com
```

Пробелы и регистр нормализуются, повторы удаляются. Неверный адрес приводит
к ошибке настройки. Пустая строка выключает административный доступ.
Выполните `uv run atrag db migrate` и перезапустите Streamlit после изменения
настройки. Миграция `0011_admin_users` добавляет статус и время входа;
существующие аккаунты и история сохраняются.

Список `access.allowed_emails` в Streamlit secrets по-прежнему применяется,
если `check_allowed_emails` включён: администратор тоже должен иметь допуск.
Роль не хранится в БД. Аккаунты определяются Google issuer/subject,
а совпадение email не объединяет пользователей.

## Users

Таблица показывает email, регистрацию, последний вход, статус и учтённые
LLM input/output/total tokens. Поиск по email, фильтр статуса и номер страницы
выполняют выборку по 25 пользователей; изменение фильтра возвращает первую
страницу. Агрегация выполняется одним SQL-запросом на страницу.

В колонке `Actions` каждой строки находится кнопка активации/деактивации.
Откроется подтверждение с email выбранного пользователя. До подтверждения
статус не меняется; отмена закрывает окно. Деактивация своего аккаунта запрещена.
На подтверждении сервис заново проверяет права администратора.

Деактивация закрывает доступ также в открытых сессиях: нельзя читать историю,
создавать диалоги, отправлять и продолжать запросы. Уже начатый запрос может
завершиться; результат, статус и доступный usage сохраняются. Повторный вход
не активирует аккаунт. Реактивация сохраняет прежние диалоги.

Последний вход — начало новой авторизованной Streamlit-сессии, включая вход
по Google cookie. Клики, сообщения и переходы между страницами не меняют дату.
Для исторических аккаунтов до нового входа показывается «Нет данных».

Учтённые токены суммируются по сохранённому usage всех ходов, включая failed
и interrupted. Повторное открытие и продолжение не добавляют счётчиков.
Embeddings не включены. Вызовы, для которых провайдер не сообщил usage, и
расход, не записанный при жёстком сбое процесса, нельзя восстановить:
показатель не является сверкой со счётом провайдера.

## Documents

Одна строка соответствует логическому документу, включая неопубликованные.
Детали содержат все подготовленные версии, даты, официальный источник
и скачивание сохранённого PDF либо ZIP с HTML-страницами и `collection.json`.
Байты читаются только при скачивании, с повторной авторизацией,
проверкой размера, checksum и границ каталога `ATRAG_DATA_DIR/raw`.

Дата загрузки — `indexed_at` установки версии в эту БД; дата подготовки
`ingested_at` показана отдельно. Размер документа — сумма размеров уникальных
исходников по `source_sha256`: повторная подготовка тех же байтов не удваивает
размер. У HTML-коллекции учитывается сумма размеров страниц. Отсутствующий
исходник отмечается в деталях и не мешает открыть таблицу.

## Термины

- Пользователь: аккаунт с постоянной парой Google issuer/subject.
- Администратор: активный допущенный пользователь с email из env.
- Документ (`source_id`): постоянная идентичность загруженного материала.
- Подготовленная версия (`snapshot_id`): неизменяемый результат подготовки.
- Исходник (`source_sha256`): уникальные байты PDF или HTML-коллекции.
- Учтённые LLM-токены: usage, сохранённый в строках ходов.

Страницы находятся внутри пакета `atrag.interface.app_pages`, поэтому входят
в существующий релизный архив и Python wheel. Навигация использует
[нативные `st.Page` и `st.navigation`](https://docs.streamlit.io/develop/concepts/multipage-apps/page-and-navigation).
