# Выполнение хода и восстановление

`TurnService.stream_turn(user, conversation_id, turn_id, text, language, *, resume=False)`
возвращает синхронный итератор событий. Пользователь берётся из
`ChatService.authenticate()`. UUID хода назначается вызывающей стороной один раз
и сохраняется при повторном открытии страницы и продолжении.

```python
from atrag.chat.api.execution import LangGraphBackend
from atrag.chat.client.model import create_chat_model
from atrag.chat.services.turns import TurnService

backend = LangGraphBackend(engine, create_chat_model(settings))
turns = TurnService(engine, backend)
events = turns.stream_turn(user, conversation_id, turn_id, question, "pt")
for event in events:
    ...  # Отображение зависит от event.kind.
```

Клиент embeddings можно передать как `LangGraphBackend(..., client=client)`.
Модель и клиент разрешено переиспользовать; граф, привязка RAG к ходу,
соединение checkpoint и блокировка создаются для отдельного исполнения.
Миграции выполняет только явная команда `atrag db migrate`.

| Событие | Данные и смысл |
| --- | --- |
| `TextDelta`, `kind="text"` | `text`: очередной публичный фрагмент модели, без reasoning и аргументов инструментов |
| `ToolActivity`, `kind="tool"` | `name`, `call_id`, `phase="started"/"completed"`: запрошенный инструмент и получение результата; тела результатов не выводятся |
| `TurnCompleted`, `kind="completed"` | `turn`: окончательный сохранённый ход с проверенным ответом, реестром источников и usage |
| `TurnError`, `kind="error"` | `code`: стабильный код для локализации в UI; детали исключения остаются на сервере |

Поток текста предварительный: только `completed` означает успешный ответ.
После завершения UI использует `turn.answer` как окончательный текст; при
восстановлении заменяет прежний предварительный вывод. `turn.sources` сохраняет
весь фактический реестр, включая материалы для исторического дочитывания.
`answer_sources(turn.answer, turn.sources)` выбирает цитируемые записи для
показа под успешным ответом. Неизвестная/пропущенная ссылка в содержательном
ответе даёт ошибку агента.

Если для ответа не хватает сведений пользователя или документа, модель выбирает
формат `ask_user`: 1–3 конкретных вопроса без налоговых выводов. Это завершённый
ход (`completed`), которому не нужны ссылки на нерелевантные результаты поиска.
UI показывает вопросы и позволяет сразу ответить в обычном поле ввода; ответ
пользователя становится следующим ходом в том же диалоге. Прежняя история,
использованные источники и учёт запросов модели сохраняются. Уточнение не
исполняет RAG-инструмент и не требует дополнительного запроса модели.

Владелец проверяется до чтения истории, checkpoint и открытия backend.
Отказ в доступе поднимает `PermissionError`; неверные входные значения или
повтор UUID с другим вопросом/языком/диалогом — `ValueError`.
`conversation_busy` означает, что другая вкладка уже исполняет этот диалог:
новая попытка не сохраняет вопрос и не вызывает модель.

Блокировка — неблокирующая PostgreSQL session advisory lock, ключ вычисляется
из UUID диалога с отдельным префиксом. Она удерживается до завершения/закрытия
итератора, не удерживая транзакцию на время модели. Другие диалоги исполняются
независимо. При закрытии соединения PostgreSQL освобождает блокировку.
Вызывающая сторона должна исчерпать итератор либо закрыть его через `close()`.

Новый ход сохраняет вопрос, язык и опубликованный состав до вызова агента.
Состояния: `pending` → `running` → `completed`; ошибка даёт `failed`, закрытие
потока — `interrupted`. При жёсткой остановке процесса остаётся `running`.
Повтор завершённого UUID возвращает сохранённый `completed` без модели и
checkpoint. Любой существующий незавершённый UUID даёт `resume_required`;
новый вопрос при незавершённой истории — `unfinished_turn`.

Продолжение запускается явным действием UI: тот же вызов с `resume=True`,
исходными UUID, вопросом и языком. Несуществующий UUID даёт `turn_not_found`.
Смена языка профиля и публикация корпуса не меняют язык или состав этого хода.
`thread_id` всегда равен строковому UUID диалога; `turn_id` и ID HumanMessage
связывают checkpoint с конкретным ходом. Если checkpoint этого хода уже есть,
передаётся `None`, вопрос повторно не добавляется. Если процесс остановился до
первого checkpoint, явное продолжение добавляет сохранённый вопрос впервые.

Используется `durability="sync"`: завершённые узлы сохраняются до перехода к
следующим. Если граф уже завершился, а запись результата в таблицу ходов
оборвалась, восстановление сохраняет готовый ответ без модели. Повторно
исполняется только работа, не зафиксированная в checkpoint. Вызов внешнего API,
оборванный до фиксации результата, может повториться при явном продолжении.
Счётчики модели восстанавливаются из transcript текущего хода; реестр, бюджет
извлечения и embeddings usage остаются в строке хода.

`execution_failed` сохраняет тип исключения и доступные публичный текст/usage;
в UI не передаются транспортные сообщения, запросы или внутренние рассуждения.
Лимиты и проверка цитат продолжают действовать при восстановлении. Нажатие
продолжения не отменяет постоянную ошибку проверки ответа или исчерпание лимита.

[восстановление исполнения](https://docs.langchain.com/oss/python/langgraph/fault-tolerance),
[потоки messages/updates](https://docs.langchain.com/oss/python/langgraph/streaming).
