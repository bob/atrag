# Агент и история

`atrag.chat.client.model.create_chat_model(settings)` создаёт `ChatOpenAI`:
модель из `ATRAG_CHAT_MODEL` (по умолчанию `gpt-6-luna`), Responses API,
reasoning `low`, до 4096 выходных токенов, timeout 60 секунд и до двух
повторов временных ошибок средствами SDK. История передаётся явно:
`use_previous_response_id=False`, `store=False`. Отсутствующий ключ
обнаруживается до создания клиента. В тестах используется HTTP-заглушка.

`atrag.chat.api.agent.build_agent(model, rag, language, checkpointer=None)`
собирает граф через `langchain.agents.create_agent`. `rag` — серверный
`RagTools` для уже созданного хода. До сборки и при начале вызова проверяется
доступ к реестру этого хода. Язык разбирается как `ru`, `en` или `pt`.
Системная инструкция требует выводов по полученным материалам, дочитывания
продолжений, исключений, примечаний, отменённых положений и таблиц;
неподтверждённый налоговый год нельзя считать установленным.

Граф принимает `{"messages": [HumanMessage(question)]}`; с checkpointer
передаётся `configurable.thread_id`, равный UUID диалога. Для следующего хода
собирается новый граф с новым `RagTools` и тем же checkpointer/thread_id.
Без checkpointer вызывающая сторона передаёт всю историю завершённых ходов
и текущий вопрос. Сервис использует сохранённые вопрос, язык и UUID хода.

В успешном результате:

| Поле | Значение |
| --- | --- |
| `answer` | Только публичный текст финального ответа |
| `sources` | Оригинальные записи реестра для упомянутых `[1]`, `[2]`, в порядке первого появления |
| `model_usage` | Число ответов модели и суммы input/output/total tokens текущего хода |
| `messages` | Полный внутренний transcript; не предназначен для вывода в UI |

UUID хода возвращается в конверте каждого выполненного RAG-инструмента.
Это позволяет модели адресовать прежнюю цитату парой `turn_id/citation_id`.
Перед использованием её в новом ответе нужно вызвать инструмент дочитывания:
источник попадёт в реестр нового хода с его локальным номером. Произвольные
номера, диапазоны и группы вида `[1, 2]` отклоняются. Если материал получен,
ответ должен ссылаться на него. При пустой выдаче допустимо объяснить пробел
или уточнить вопрос без цитат. Текст, версии и местоположения источников
никогда не берутся из модельного ответа.

Один middleware проверяет бюджет по transcript текущего хода: не более
8 вызовов модели и 6 вызовов инструментов. Седьмой инструмент отклоняется
до выполнения; пакет параллельных вызовов, превышающий остаток, отклоняется
целиком. Ошибочные аргументы также расходуют разрешение на вызов. Счётчики
не разделяют изменяемое состояние между экземплярами агента. Лимиты
извлечения 6000/24000 остаются в `RagService` и PostgreSQL.

Перед каждым вызовом модели `bounded_messages` оставляет последние целые
завершённые ходы и текущий ход. Бюджет 32000 включает системную инструкцию,
схемы инструментов и сериализованные сообщения; локальная оценка использует
`o200k_base` с дополнительным запасом на обрамление сообщений. Проверяются
пары вызовов/результатов. Если текущий ход не помещается, возникает
`HistoryBudgetExceeded`; его текст и источники не обрезаются. Сокращается
только копия запроса: полная история остаётся в checkpoint PostgreSQL.

Неизвестные/пропущенные ссылки, пустой ответ, незавершённые вызовы,
`status=incomplete/failed` и остановка по длине/фильтру дают `InvalidAnswer`.
Превышение числа вызовов даёт `AgentLimitExceeded`; ошибки API и timeout
передаются сервису. Эти ошибки не возвращают успешный результат. Поля
предыдущего успешного ответа очищаются в начале нового вызова графа.

`TurnService` проверяет владельца **до чтения checkpoint**, сериализует
исполнение, сохраняет ответ/status/usage в ходе, обеспечивает идемпотентный
UUID и явное восстановление. Низкоуровневый граф этих переходов не выполняет.
События, ошибки и правила продолжения: [EXECUTION.md](EXECUTION.md).
