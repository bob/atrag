# Интерфейс Streamlit

Подготовьте `.env`, Google OIDC и allowlist по
[инструкции настройки](README.md#6-настройка-базового-каркаса).
Затем из корня проекта:

```sh
uv sync --locked
uv run atrag db migrate
uv run streamlit run streamlit_app.py
```

Миграция выполняется отдельной командой. Открытие интерфейса её не вызывает.
Ключ OpenAI нужен при выполнении ответа; экран входа не открывает БД или модель,
а чтение истории не создаёт модель. Вход вызывает `st.login("google")`,
выход — `st.logout()`. Только нативный `st.user` передаётся в ChatService.
Allowlist и подтверждённый Google email проверяются на каждом обновлении.
Claims из URL и Session State не используются для аутентификации.

В боковой панели доступны новый диалог, список собственных диалогов,
переключатель ru/en/pt, опубликованные документы и их версии, выход.
Пустые и одинаковые заголовки различаются номером в списке.
URL `?conversation=<UUID>` проверяется по текущему владельцу до истории;
некорректный, повторённый или чужой UUID даёт отказ в доступе.
Native `bind` здесь не подходит: Streamlit сериализует отображаемую подпись,
а заголовки и порядок меняются. URL синхронизируется с UUID отдельно.

История всегда читается через сервис, а не из Session State. Новый вопрос
получает UUID один раз при отправке. Обновление страницы и изменение языка
не запускают выполнение. Незавершённый ход блокирует следующий вопрос;
кнопка продолжения передаёт прежние UUID, вопрос и язык с `resume=True`.
PostgreSQL-сервис сериализует конкурирующие запросы разных вкладок.

Язык сохраняется в БД и действует на интерфейс и следующие ответы.
Сохранение происходит только при явном переключении: обычный rerun старой
вкладки не перезаписывает предпочтение, изменённое в другой сессии.
Прежние вопросы, ответы и цитаты остаются на исходном языке. Поток показывает
только публичный текст и этапы поиска/чтения, без рассуждений модели.
Источники под ответом показывают исходную версию, PDF/HTML/DOCX-местоположение,
редакцию, выдержки, таблицы, заметки и неполноту текста. Текущий состав
в боковой панели читается заново и не подменяет версии прежних цитат.

`st.cache_resource` используется только для SQLAlchemy engine и модели.
ChatService, TurnService, граф, пользователь, история и корпус не кешируются.
Генератор сервиса закрывается при остановке UI, сохраняя возможность продолжения.
Технические исключения и внутренние данные подключения пользователю не выводятся.

AppTest проверяет интерфейс с подставными сервисами, отдельно — настоящие
PostgreSQL-сервисы и checkpoints с локальной LangChain-моделью.
Для установленного Streamlit 1.66.1 OIDC claims в тестах подставляются на
границе `st.user`: `AppTest.user` и agent HTTP API в этой установке отсутствуют.
Проверка работающего сервера использует отдельный временный launcher с
подставной моделью и protobuf/WebSocket API Streamlit. Проверены загрузка,
создание диалога, ответ, язык и повторное открытие истории; серверный журнал
без ошибок и предупреждений. Визуальная браузерная проверка недоступна:
Computer Use отклонил текущий URL. В production entrypoint обхода
аутентификации нет.
Google и платный OpenAI отдельно не проверялись.
