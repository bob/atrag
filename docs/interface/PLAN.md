# План реализации интерфейса

Требования: [README.md](README.md). Нумерация разделов требований не является
порядком реализации. Этот план разбивает работу на проверяемые шаги.

## Порядок работы

Для каждого шага применять `ub-mode`:

1. Зафиксировать ожидаемое поведение тестом и увидеть ожидаемое падение.
   Если честный тест непрактичен, записать причину и способ проверки.
2. Внести минимальное изменение, достаточное для прохождения проверки.
3. Проверить границы данных, убрать дублирование и лишнюю сложность.
   Выполнить crapper (`CRAP < 10`), dryer (дублирование `< 0.8`) и mutator
   для затронутого кода; разобрать непокрытые участки и выжившие мутации.
4. Выполнить подходящие тесты, Ruff check/format и проверку типов изменённого
   Python-кода. Сохранить runtime Python 3.14, синтаксис Python 3.13 и `py313`.
5. Обновить журнал действий и статус шага, сохранить небольшой коммит с
   причиной, изменениями и проверкой. В конце работы отправить коммиты в `master`.

PostgreSQL проверять в существующей `atrag_test_context_20261101`:
очищать тестовые таблицы, не пересоздавать базу. Обычные тесты используют
подставные модели и не вызывают платные API.

## Шаг 1. Базовый каркас

**Результат:** окружение и схема хранения готовы к реализации чата.

- Добавить Streamlit с auth, LangChain, LangChain OpenAI и LangGraph;
  обновить `uv.lock`.
- Добавить в существующие `.env`-настройки модель чата и идентификатор снимка
  CIRS. Сохранить возможность пользоваться ingestion/CLI без настроенного чата.
- Создать таблицы пользователей, диалогов и ходов через Alembic. Зафиксировать
  идентичность пользователя парой issuer/subject, язык, владельца диалога,
  снимок, постоянный UUID хода, вопрос, ответ, источники, статус и usage.
- Создавать таблицы `PostgresSaver` явным шагом команды `atrag db migrate`.
  Миграции должны допускать повторный запуск и восстановление после сбоя.
- Настроить игнорирование локального `secrets.toml` и предоставить отслеживаемый
  шаблон Google OIDC/списка разрешённых адресов; описать callback и настройку.

**Готово, когда:** настройки читаются с прежним приоритетом окружения;
некорректные значения отклоняются; миграция обновляет существующий корпус,
повторный запуск сохраняет данные; ограничения БД не допускают неверных связей
и повторного UUID; откат таблиц чата сохраняет корпус; checkpoint сохраняется
и читается через новое соединение. Проверить также весь существующий набор тестов.

В этот шаг не входят экран входа, агент и отправка сообщений.

## Шаг 2. Доступ и собственные диалоги

**Результат:** проверенная Google-идентичность получает доступ только к своим данным.

- В независимом от Streamlit пакете `atrag.chat` разобрать claims на границе:
  Google issuer, subject, подтверждённый email и список разрешённых адресов.
- Реализовать создание/чтение пользователя, сохранение языка, создание и список
  диалогов, загрузку истории. Все операции с диалогом требуют текущего пользователя.
- Закреплять настроенный проиндексированный снимок при создании диалога;
  название получать из первого вопроса без LLM.

**Готово, когда:** неподтверждённый/запрещённый адрес отклоняется; email не
подменяет идентичность; два пользователя не могут читать или менять чужой
диалог; смена языка и история сохраняются после открытия нового соединения.

## Шаг 3. Инструменты RAG и реестр источников

**Результат:** агент может безопасно получать материалы через четыре инструмента.

- Обернуть существующие `search_tax_documents`, `load_unit_text`,
  `load_neighbor_parts`, `load_context`, не меняя алгоритмы поиска и embeddings.
- Передавать снимок, соединения и пользователя со стороны приложения;
  проверять аргументы модели на входе.
- Собирать реестр из фактической выдачи: стабильные номера цитат, португальские
  выдержки, адреса, страницы, редакция и замечания.
- Ограничить одно извлечение 6000 токенов и сумму извлечений за ход 24 000.

**Готово, когда:** поиск и дочитывание возвращают ожидаемые материалы;
пустая выдача, неверные аргументы и исчерпание бюджета дают определённый
результат; модель не может заменить снимок или владельца; источники сохраняют
замечания, признаки неполного текста и корректные страницы.

## Шаг 4. Агент и ограниченная история

**Результат:** `create_agent` отвечает по материалам корпуса с проверенными ссылками.

- Настроить `ChatOpenAI` и Responses API согласно требованиям, системную
  инструкцию и инструменты шага 3.
- Ограничить ход 8 вызовами модели и 6 инструментами; reasoning `low`,
  выход 4096 токенов, timeout 60 секунд, до двух повторов временных ошибок.
- Подавать до 32 000 токенов истории, удаляя старые завершённые ходы целиком
  и сохраняя пары вызовов/результатов инструментов. Полную историю хранить в БД.
- Проверять ссылки по реестру; некорректный ответ не завершать успешно.

**Готово, когда:** подставная модель проходит поиск, дочитывание и продолжение
разговора; отсутствие данных, неверные ссылки, лимиты, timeout и ошибки API
проверены; усечение истории не оставляет вызов инструмента без результата.

## Шаг 5. Выполнение хода и восстановление

**Результат:** `stream_turn(user, conversation_id, turn_id, text, language)`
надёжно выдаёт события текста, инструментов, завершения и ошибки.

- Проверять владельца до доступа к истории/checkpoints; использовать UUID
  диалога как `thread_id`.
- Сериализовать выполнение PostgreSQL advisory lock на диалог. Сохранять ход
  под постоянным UUID, не добавлять вопрос и не запускать модель повторно при rerun.
- Сохранять текст, источники, usage и состояние выполнения. После сбоя
  продолжать только по явному запросу с последнего checkpoint.

**Готово, когда:** повторный UUID, обновление страницы и две вкладки не
дублируют ход; независимые диалоги работают отдельно; сбой сохраняет состояние;
продолжение не добавляет вопрос повторно; чужое состояние недоступно.

## Шаг 6. Streamlit и три языка

**Результат:** пользователь работает с чатом через `streamlit_app.py`.

- Подключить нативный Google OIDC и проверки шага 2.
- Добавить боковую панель, создание/переключение диалогов, язык, редакцию и выход.
  Восстанавливать диалог из URL только после проверки доступа.
- Отображать события сервиса через нативные chat/status/stream/expander;
  выводить источники под ответом и кнопку продолжения после сбоя.
- Перевести подписи, статусы и ошибки на ru/en/pt. Изменение языка влияет
  на следующие ответы; существующие сообщения сохраняются.
- Кешировать только общие клиенты и пулы через `st.cache_resource`.
  Не выполнять миграции при открытии страницы.

**Готово, когда:** AppTest проверяет вход, отказ, создание и переключение,
три локали, источники, URL и восстановление; работающий Streamlit проверен
с подставной моделью и без ошибок в серверном журнале.

## Шаг 7. Приёмка и документация запуска

**Результат:** весь сценарий воспроизводится по инструкции из чистого окружения.

- Проверить резидентство, исключения 16(4), переходные примечания,
  связь 68-A → 68 с таблицами, пробел статьи 100 и вопрос вне корпуса.
- Проверить двух пользователей, перезапуск, обновление страницы, две вкладки,
  лимиты и восстановление после сбоя.
- Завершить README: настройки, Google callback, миграции и
  `uv run streamlit run streamlit_app.py`.
- Выполнить полный набор тестов и проверки качества; проверить оставшиеся
  временные worktree/исполнители и убрать только безопасные остатки.

**Готово, когда:** все автоматические проверки и работающий интерфейс
с подставной моделью проходят. Живые Google/OpenAI проверяются отдельно
с настроенными учётными данными и согласованными API-вызовами; результат
фиксируется отдельно от автоматической приёмки.

## Термины хранения

- **Пользователь:** идентичность OIDC `(issuer, subject)`; email служит для допуска.
- **Диалог:** история одного владельца, закреплённая за одним снимком CIRS.
- **Ход:** один вопрос и его выполнение с постоянным UUID, ответом и источниками.
- **Checkpoint:** сохранённое состояние агента внутри `thread_id` диалога.
- **Источник:** фактический материал инструмента, на который ссылается ответ.
