# Инструменты RAG и источники

Шаг 3 предоставляет `atrag.chat.api.tools.RagTools`, независимый от Streamlit.
После `ChatService.start_turn(...)` сервер создаёт экземпляр:

```python
rag = RagTools(engine, user, conversation_id, turn_id, client=embedding_client)
tools = rag.tools
```

`user` приходит из `ChatService.authenticate()`. UUID диалога и хода,
соединения и клиент embeddings задаёт приложение. Модель получает только
схемы четырёх `StructuredTool`; поля владельца, состава и соединений в них
отсутствуют, лишние аргументы запрещены. Каждый вызов заново проверяет
владельца и принадлежность хода диалогу.

| Инструмент | Аргументы модели |
| --- | --- |
| `search_tax_documents` | `query`, `limit` (1–50), необязательные `source_ids` и юридические `filters` |
| `load_unit_text` | `address`, `start` для продолжения текста |
| `load_neighbor_parts` | `address` фрагмента, `before`, `after` |
| `load_context` | `address`, доступные `reference_ids`, `note_ids`, проверяемые `dependency_edges` |

Все инструменты принимают `context_tokens` от 1 до 6000. Язык поиска берётся
из сохранённого хода. `source_ids` сужает его опубликованный состав; пустой
список выбирает пустую область. Попытка выбрать посторонний документ
отклоняется. Семантический поиск готовит один embedding запроса в общем
пространстве, ранжирует кандидатов всех выбранных документов вместе и
применяет общий top-k и бюджет. Точный поиск сохраняет порядок адресов и
частей. CLI поиска по одному снимку продолжает работать.

Прямой адрес имеет вид:

```json
{"kind": "fragment", "source_id": "pt-at-cirs", "snapshot_id": "<64 hex>", "block_id": "<fragment_id>"}
```

`kind: "unit"` адресует `legal_unit_id`. Для дочитывания сохранённого источника
можно передать:

```json
{"kind": "citation", "turn_id": "<UUID прежнего хода>", "citation_id": 1}
```

Прямой адрес разрешается только в составе текущего хода. Адрес цитаты
разрешается по сохранённому реестру того же диалога и читает исходную версию,
даже если документ заменён или исключён из нового состава. Цитаты других
диалогов недоступны, включая другие собственные диалоги пользователя.
Старые записи источников без нового адресного контракта сохраняются как
история; инструмент не угадывает их идентичность.

Результат выполненного инструмента содержит серверный `turn_id`, `status`,
`sources` и `context_tokens_used`. UUID нужен агенту для адресации цитат
этого хода в последующей истории. Поиск также
возвращает оценки и vector ranks в `hits`, соответствующих `sources` по порядку.
Возможные статусы: `ok`, `no_match`, `budget_exhausted`, `invalid_arguments`.
Ошибки схемы LangChain возвращает JSON-строкой; результат выполненного
инструмента — JSON-совместимый словарь. Отказ в доступе вызывает
`PermissionError` для обработки сервисом. Ошибки инфраструктуры не превращаются
в пустую выдачу. Неполный результат сохраняет `complete`, `next_start` либо
списки пропущенных блоков, таблиц и частей.

Источники создаются из фактически полученных срезов. Они включают адрес,
номер цитаты, оригинальный текст, границы среза и длину исходного блока,
название документа, язык, редакцию и даты, юридическую подпись и статус,
типизированные местоположения, редакционные примечания, замечания подготовки,
диагностику и доступные адреса дочитывания. Геометрия PDF в ответ не входит.
Местоположения PDF задаются страницами, HTML — разделом/якорем,
DOCX — разделом/абзацем. Для HTML/DOCX не нужны фиктивные страницы.

Номера цитат последовательны внутри хода. Повтор того же адреса и среза с теми
же данными сохраняет номер; другая версия, документ или срез получает новый.
Реестр и счётчик `retrieval_tokens` сохраняются атомарно в `chat_turns` под
блокировкой строки. Повторное создание экземпляра и конкурирующие инструменты
делят общий предел 24 000 токенов. Повторное извлечение тратит бюджет снова.
Извлечение учитывает исходный текст, подписи, редакционные примечания и
доставленные таблицы; служебные адреса и геометрия в бюджет текста не входят.
Usage embeddings суммируется в сохранённом ходе.

Миграция `0007_rag_evidence` добавляет ограниченный счётчик и разрешает
отсутствующие страницы для типизированного HTML/DOCX-местоположения. Старые
источники и история сохраняются. Пустое поле `location` не сериализуется в
прежние PDF-артефакты и не меняет их хеши. Новые загрузчики форматов в этот
шаг не входят; контракт проверяется синтетическим подготовленным материалом.

Схемы инструментов сверены с [документацией LangChain](https://docs.langchain.com/oss/python/langchain/tools#advanced-schema-definition).
