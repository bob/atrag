# Чат для работы с RAG в ATRAG

Этот документ фиксирует требования. Порядок реализации и критерии готовности
каждого шага: [PLAN.md](PLAN.md).

## 1. Результат и границы первой версии

Создать приложение Streamlit для нескольких пользователей: вход через Google по списку разрешённых адресов, отдельные диалоги в PostgreSQL и агент LangChain, который самостоятельно вызывает инструменты RAG.

Первая версия работает с уже проиндексированным CIRS. Интерфейс и ответы поддерживают русский, английский и португальский; исходные цитаты остаются на португальском. Загрузка документов, просмотр PDF и развёртывание сервиса в эту реализацию не входят.

## 2. Интерфейс и доступ

- Точка входа — `streamlit_app.py`. Использовать нативные `st.chat_message`, `st.chat_input`, `st.write_stream`, `st.status` и `st.expander`.
- Боковая панель: новый диалог, список собственных диалогов, переключатель языка, сведения о редакции CIRS и выход. Название диалога формировать из первого вопроса без дополнительного вызова LLM.
- Выбранный язык переводит подписи, статусы, ошибки и последующие ответы. Предпочтение сохраняется для пользователя; существующие сообщения не переводятся.
- При генерации показывать текст потоком и краткие этапы работы: поиск, чтение статьи, подготовка ответа. Внутренние рассуждения модели не выводить.
- В ответе использовать ссылки `[1]`, `[2]`. Под ним показывать соответствующие оригинальные выдержки, юридические адреса, страницы, редакцию и относящиеся к материалу замечания.
- Вход реализовать через нативный [OIDC-механизм Streamlit](https://docs.streamlit.io/develop/concepts/connections/authentication). Допускать только подтверждённые Google-адреса из конфигурационного списка. Владельца определять по идентичности провайдера, а не по значению из интерфейса.
- Любое чтение диалога, отправку сообщения и восстановление состояния проверять на принадлежность текущему пользователю. Выбор диалога сохранять в URL; повторное открытие страницы восстанавливает его после проверки доступа.

## 3. Агент и инструменты RAG

Отделить бизнес-логику в пакет `atrag.chat`, независимый от Streamlit.

- Использовать `langchain.agents.create_agent` и `ChatOpenAI(model="gpt-6-luna", use_responses_api=True)`. Responses API поддерживает вызовы инструментов с выбранной моделью. [Документация модели](https://developers.openai.com/api/docs/models/gpt-6-luna), [интеграция LangChain](https://docs.langchain.com/oss/python/integrations/chat/openai).
- Подключить четыре инструмента поверх существующих сервисов: `search_tax_documents`, `load_unit_text`, `load_neighbor_parts`, `load_context`. Поисковые алгоритмы и подготовку embeddings корпуса сохранить.
- Идентификатор снимка, соединения и пользовательский контекст передавать инструментам со стороны приложения. Модель задаёт поисковый запрос, фильтры и необходимые юридические адреса.
- В системной инструкции закрепить: налоговые выводы только по полученным материалам; учитывать продолжения, исключения, примечания и отменённые положения; при недостатке данных уточнять вопрос или сообщать о пробеле. Применимость к неподтверждённому налоговому году не утверждать.
- Реестр источников формировать из фактических результатов инструментов. Проверять идентификаторы цитат; страницы и выдержки брать из этого реестра. Ответ с некорректными ссылками не отмечать как успешно завершённый.
- Начальные ограничения: до 8 вызовов модели и 6 инструментов за ход, до 6000 токенов на одну операцию извлечения и 24 000 суммарно за ход. Для модели: reasoning `low`, максимум 4096 выходных токенов, timeout 60 секунд, до двух повторов временных ошибок.
- Историю для LLM ограничивать бюджетом 32 000 токенов, убирая старые завершённые ходы целиком и сохраняя согласованность вызовов инструментов. Полная сохранённая история остаётся доступной в интерфейсе.

Внутренний интерфейс сервиса: `stream_turn(user, conversation_id, turn_id, text, language)` возвращает события текста, работы инструментов, завершения и ошибки. Streamlit отвечает только за их отображение.

## 4. PostgreSQL, состояние и конфигурация

- Добавить таблицы пользователей, диалогов и ходов. Хранить владельца, язык пользователя, закреплённый снимок диалога, тексты сообщений, источники, статусы выполнения и usage модели/embeddings.
- Состояние агента сохранять через `PostgresSaver`; `thread_id` соответствует диалогу. Session State использовать для состояния интерфейса.
- Каждому ходу назначать постоянный UUID. Повторное выполнение страницы не должно добавлять сообщение или запускать модель повторно.
- Выполнение в одном диалоге сериализовать PostgreSQL advisory lock. При сбое сохранять незавершённый статус; продолжение запускать только явной кнопкой, с последнего checkpoint и без повторного добавления вопроса.
- Кешировать общие клиенты и пулы соединений через `st.cache_resource`. Пользовательские сообщения и результаты не помещать в общий кеш.
- Добавить зависимости Streamlit с поддержкой auth, LangChain, LangChain OpenAI и LangGraph; обновить lock-файл.
- Сохранить существующий механизм `.env` для OpenAI и PostgreSQL. Добавить настройки модели и снимка CIRS. Google OIDC и список разрешённых адресов задавать через Streamlit secrets; предоставить шаблон без секретов.
- Таблицы приложения создавать миграцией Alembic, таблицы checkpoints — явным шагом команды миграции. Открытие интерфейса миграции не выполняет.
- Документировать настройку Google callback, миграции и запуск командой `uv run streamlit run streamlit_app.py`.

## 5. Проверки и критерии готовности

- **Агент:** поиск, последовательное дочитывание, продолжение разговора, пустая выдача, некорректные аргументы, ограничения бюджета, timeout и ошибки OpenAI.
- **Источники:** корректные ссылки и страницы; отсутствие выдуманных цитат; сохранение замечаний и признаков неполного текста.
- **Предметные сценарии:** резидентство, исключения статьи 16(4), переходные примечания, связь 68-A → 68 с таблицами, известный пробел статьи 100 и вопрос вне корпуса.
- **Доступ и сохранение:** два пользователя не видят чужие диалоги; история восстанавливается после перезапуска; обновление страницы и две вкладки не дублируют ход.
- **Streamlit AppTest:** экран входа, отказ в доступе, создание и переключение диалогов, три локали, источники и восстановление после ошибки. В обычных тестах использовать подставную модель без платных запросов.
- PostgreSQL-тесты выполнять в существующей `atrag_test_context_20261101`, очищая тестовые таблицы без пересоздания базы.
- Проверить изменённые Python-файлы через `ruff check`, `ruff format --check` и проверку типов. Сохранить runtime Python 3.14, синтаксис Python 3.13 и Ruff target `py313`.
- Завершить проверкой работающего Streamlit с подставной моделью. Живую проверку Google и OpenAI выполнять отдельно с настроенными учётными данными и согласованными API-вызовами.

## 6. Настройка базового каркаса

Шаг 1 подготавливает зависимости, настройки и хранилище. Экран входа,
выполнение агента и `streamlit_app.py` относятся к последующим шагам
[плана](PLAN.md).

```sh
uv sync --locked
uv run atrag config check
uv run atrag db migrate
```

В существующий `.env` можно добавить:

```dotenv
ATRAG_CHAT_MODEL=gpt-6-luna
ATRAG_CHAT_SNAPSHOT_ID=
```

`ATRAG_CHAT_SNAPSHOT_ID` — 64 строчные шестнадцатеричные цифры идентификатора
уже проиндексированного снимка CIRS. Его можно взять из результата
`atrag ingest index`. Пустое значение означает, что снимок для чата ещё
не выбран; существующие команды подготовки и поиска продолжают работать.
Значения окружения процесса имеют приоритет над `.env`.
`config check` показывает модель и снимок, не открывая соединение с БД.
Проверка существования снимка и прав пользователя выполняется при работе
с диалогами в шаге 2.

`atrag db migrate` применяет Alembic до `0004_chat`, затем явно вызывает
`PostgresSaver.setup()` на отдельном autocommit-соединении. Оно нужно для
`CREATE INDEX CONCURRENTLY`. Оба этапа защищены одной сессионной advisory lock;
ожидающие миграции проверяют её без открытой транзакции, чтобы не блокировать
построение индексов. При сбое второго этапа первый остаётся применённым, а повторная команда
завершает настройку. Открытие будущего интерфейса не выполняет миграций.
При откате `0004_chat` удаляются данные чата; корпус и таблицы checkpoints
не затрагиваются. Такая операция предназначена только для осознанного отката.

Для будущего Google OIDC скопировать отслеживаемый шаблон:

```sh
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
```

Локальный `.streamlit/secrets.toml` игнорируется Git. В Google Auth Platform
создать OAuth-клиент типа Web application и добавить точный redirect URI
`http://localhost:8501/oauth2callback`. Для другого порта/адреса одинаково
изменить URI у клиента Google и в secrets. Заполнить `auth.google.client_id`,
`auth.google.client_secret`, задать случайный длинный `auth.cookie_secret`
и перечислить допустимые адреса в `access.allowed_emails`. Если приложение
Google находится в режиме Testing, также добавить их в Test users.
Формат auth и callback соответствует
[официальной инструкции Streamlit](https://docs.streamlit.io/develop/tutorials/authentication/google).
Проверка разрешённых адресов и `email_verified` будет реализована в шаге 2;
сам шаблон ещё не реализует допуск.

После реализации шага 6 приложение запускается командой:

```sh
uv run streamlit run streamlit_app.py
```
