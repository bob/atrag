## Что изменилось

`normalize_address()` распознаёт адрес по всей строке: `CIRS 16` и
`artigo 16 do CIRS` остаются точным поиском без embeddings. Смысловой вопрос
с таким упоминанием ищет также FAQ. Оба пути поиска используют это решение.

Общий смысловой поиск получает один query embedding и до 200 кандидатов
из снимков сохранённого хода. Прежнее окно 50 исключало CIRS 15(1), находившийся
на местах 117–129, когда подробные FAQ занимали начало выдачи.

`gpt-6-luna` возвращает отдельный семантический порядок кандидатов.
Сервер объединяет его с исходным векторным порядком:

```text
fusion_score = 1 / dense_rank + 1 / semantic_rank
```

Позиции начинаются с 1; при равенстве сохраняется исходный порядок. Не выбранные
моделью кандидаты продолжают её порядок в исходной последовательности.
Семантический список содержит до `2 * limit` позиций для последующего подбора
под бюджет. Окончательные top-k и бюджет остаются в общем `fit_hits`.
Ни веса, ни квоты источников, ни правила для конкретных статей не добавлены.
Оба ранга независимы: модель не может единолично вытеснить релевантный FAQ
или назначить конечные цитаты. Поле `score` остаётся исходным cosine score,
`vector_rank` — исходной векторной позицией; порядок результатов определяется
объединённым рангом.

JSON Schema задаёт точную длину списка и диапазон ID; сервер дополнительно
проверяет уникальность, завершённость ответа и usage. Оригинальные тексты,
адреса и цитаты берутся только из найденных сервером фрагментов. Сбой API или
неправильный ответ — операционная ошибка; источники не записываются.
`store=False`. Точные адреса не вызывают reranker; если все кандидаты помещаются
в запрошенный limit, дополнительный вызов также не нужен.

`source_ids` и юридические фильтры применяются **до** вызовов API и ранжирования.
Индексация сама не публикует источник. Публикация, откат и читатели остались
общими; миграция БД не потребовалась. Usage reranker сохраняется отдельно
в `embedding_usage.reranking`, не увеличивая embedding-счётчики.
