## Восстановление при первом импорте

Во время первого вспомогательного импорта сервер перестал отвечать:
SSH timeout, публичный HTTP 522, AWS Instance StatusCheckFailed=1 при
System StatusCheckFailed=0. Простая перезагрузка доступа не восстановила.
Принудительная остановка и запуск вернули сервер в рабочее состояние;
диски и статический адрес сохранены. PostgreSQL подтвердил прежний
CIRS-only release и отсутствие FAQ-снимков: частичного импорта не было.

Первый скрипт удерживал проверенный пакет в памяти во время повторной
загрузки того же пакета индексатором и планировал ещё один импорт.
Локальное измерение одной загрузки показало peak RSS 367 МиБ; при
доступных на исходном сервере примерно 587 МиБ дополнительная копия
создавала существенный риск перегрузки. Точная причина зависания по
журналам не установлена: предыдущий kernel journal недоступен.

Повтор выполнен без предварительной удерживаемой копии и без повторного
production-импорта, в отдельном systemd unit: MemoryMax=600M,
MemoryHigh=500M, CPUQuota=50%, RuntimeMaxSec=360. Job переживает потерю
SSH-соединения. Он успешно завершился за **24 секунды** (11 секунд CPU).
Живая приёмка прошла в отдельном таком же ограниченном процессе.

```sh
cd /opt/atrag/current

  .venv/bin/atrag corpus publish \
  --changes /opt/atrag/shared/data/faq-production-20261108/rollback.json
sudo install -o atrag -g atrag -m 0640 \
  /var/backups/atrag/faq-20261108/corpus-expected.json \
  /opt/atrag/shared/corpus-expected.json
sudo install -o atrag -g atrag -m 0640 \
  /var/backups/atrag/faq-20261108/corpus-changes.json \
  /opt/atrag/shared/corpus-changes.json
sudo /usr/local/sbin/atrag-control run \
  5675a84874cd002983771cdfed991467d65258af smoke
```
