# Шаг 4: общий chunk/embed/package/index

Реализован 07.11.2026 в ветке `faq-ingestion-plan`. Следующий этап — Шаг 5:
проверка общего поиска и публикация. Проверки этого этапа используют сохранённый
HTML и синтетические векторы; настоящая векторизация и публикация не выполнялись.

## Результат

`ingest parse --extracted ... --registry data/sources/faq.json` переводит проверенное
извлечение в общие `LegalUnit`: тема → `faq_entry`. `text_original` единицы FAQ
содержит полный ответ; `faq` хранит вопрос, ответ, номер, тему, ссылки и исходное
местоположение. Текстовые отсылки остаются в оригинале ответа. Юридические адреса
и PDF-координаты не создаются.

Выбор единиц и контекст вынесены в `chunk_policy.py`; диапазоны, токенизация,
ограничения таблиц и сборка частей остаются общими. Каждый FAQ разбивается
самостоятельно. В embedding input повторяются название источника, тема, номер
и вопрос. Короткий первый абзац ответа повторяется в следующих частях, если
помещается в четверть целевого бюджета. Точные срезы всех частей восстанавливают
полный ответ, включая пробелы и переносы строк.

Общие контейнеры таблиц читают PDF и HTML. Числовые строки HTML-таблицы связываются
с исходным ответом без изменения текста. Неоднозначное совпадение блокирует
подготовку; пустая таблица оформления сохраняется в документе без вымышленного
текстового диапазона. Все 18 таблиц сохранённого снимка остаются в пакете и БД:
15 содержат текст, 3 пусты.

HTML-пакет v3 явно перечисляет `source_format` и `source_files`: manifest коллекции
и каждый HTML-файл. До открытия транзакции проверяются хеши и размеры исходников,
отношения стадий, единицы, диапазоны, полнота FAQ, таблицы, токены и полный набор
векторов. Установка исходников и импорт не вызывают HTML-парсер. Повторный импорт
сохраняет прежний индекс; ошибка внутри транзакции откатывает новую версию целиком.

Идентичность v3 исключает UUID/время попытки и статистику embedding API/кеша.
Повторная подготовка тех же материалов и векторов сохраняет `snapshot_id`; при
повторной сборке в тот же каталог остаётся первый проверенный пакет со своим
происхождением. Изменение материала, исходников, параметров или векторов создаёт
новую версию. Все файлы попытки по-прежнему проверяются по хешам. Формат и прежние
идентичности CIRS v1/v2 сохранены.

Синтетические векторы подтверждают путь подготовки/импорта, а не качество поиска.
Стоимость и реальный usage не измерялись. Перед платной векторизацией нужно
прочитать параметры **выбранного опубликованного CIRS**, а затем явно задать
`OPENAI_EMBEDDING_MODEL` и `OPENAI_EMBEDDING_DIMENSIONS` с теми же значениями:

```sql
SELECT s.snapshot_id, s.embedding_model, s.embedding_dimensions
FROM corpus_state AS c
JOIN corpus_members AS m ON m.release_id = c.release_id
JOIN source_snapshots AS s ON s.snapshot_id = m.snapshot_id
WHERE m.source_id = 'pt-at-cirs';
```

## Воспроизведение

Полный локальный сценарий вызывает настоящие команды CLI и подставляет только
embedding API. Он требует сохранённый снимок и уже существующую локальную тестовую
БД. Он не обращается к сайту, не вызывает платные модели и не публикует корпус.
Синтетические данные хранятся отдельно от настоящих пакетов:

```bash
.venv/bin/python tools/faq_ingestion_smoke.py \
  --snapshot data/faq-step2-20261107/raw/8773a9e3f191d0c9ec88ac25326497fc3cdeeb6973338c3acae6f98b65bc277d/manifest.json \
  --data-dir data/faq-step4-synthetic \
  --database-url postgresql://localhost/atrag_test_context_20261101
```

Повтор той же команды проверяет переиспользование кеша и версии. Пакет находится
в `data/faq-step4-synthetic/package/manifest.json`, отчёт — рядом в
`verification.json`. Скрипт допускает только БД с именем `atrag_test_*`; базу
не создаёт и не удаляет. Тестовые таблицы очищаются интеграционными fixtures.

Сценарий выполняет последовательно `db migrate`, `ingest extract`, `parse`,
`chunk`, `embed` дважды, `package` и `index` дважды. Все промежуточные стадии
записывают собственные `runs/<run_id>/manifest.json`.

Постоянные проверки:

```bash
.venv/bin/pytest -q tests/test_faq_pipeline.py
ATRAG_TEST_DATABASE_URL=postgresql://localhost/atrag_test_context_20261101 \
  .venv/bin/pytest -q tests/integration/test_faq_ingestion.py
```

Окончательные результаты проверок и коммиты записаны в [журнале действий](ACTION_LOG.md).
Полные HTML, векторы и пакет находятся вне Git. Перенос и push в `master`
не выполняются по прежнему указанию пользователя.
