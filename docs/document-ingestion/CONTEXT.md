# Контекст по запросу

Поиск возвращает ранжированные части в пределах `context_tokens`, по умолчанию
6000. Каждая часть содержит источник PDF, снимок, страницы, исходные диапазоны
и формулировки отсылок. `available_reference_ids` — доступные адресаты, без
автоматического включения их текстов. `related_units` и `related_tables` в
обычной выдаче пусты; таблицы самой части остаются в `fragment.tables`.

Для оригинала и продолжения использовать операции из [контракта частей](PARTS.md).
Выбранные отсылки и примечания загружаются через `load_context`:

```python
from atrag.retrieval.text import load_context
from atrag.schemas.retrieval import ContextRequest

evidence = load_context(
    ContextRequest(
        snapshot_id=snapshot_id,
        legal_unit_id="pt:cirs:code:article:68-A:paragraph:1",
        reference_ids=["pt:cirs:code:article:68"],
        context_tokens=6000,
    ),
    engine=engine,
)
```

Возвращаются исходный выбранный текст 68-A(1), статья 68 и две проверенные
таблицы. Полный текст главы не загружается через родительскую связь.
`note_ids` выбирает только примечания, доступные из исходной единицы или её
родителей. Отменённый статус 16(8) и роль примечания `transitional` сохраняются.

Для объяснения исключений вызывающий код передаёт проверенный граф зависимостей:

```python
p = "pt:cirs:code:article:16:paragraph:"
request = ContextRequest(
    snapshot_id=snapshot_id,
    legal_unit_id=p + "4",
    dependency_edges=[
        (p + "4", p + "14"),
        (p + "4", p + "16"),
        (p + "14", p + "15"),
        (p + "15", p + "14"),
    ],
)
evidence = load_context(request, engine=engine)
```

Каждое ребро должно соответствовать разрешённой исходной отсылке, прямой либо
обратной. Наличие связи само по себе не устанавливает юридическую обязательность:
граф выбирается и проверяется для вопроса. Обычные упоминания не обходятся
рекурсивно. Обход идёт в устойчивом порядке с учётом посещённых адресов;
отсоединённые зависимости, неизвестные адресаты и другой снимок отклоняются.

Первым резервируется исходный текст. Каждая возвращённая `UnitText` содержит
источник, локаторы, `[source_start, source_end)`, `source_length`, `complete`
и `next_start`. При недостатке бюджета продолжение доступно через
`load_unit_text(..., start=next_start)`. Полностью не поместившиеся единицы
перечисляются в `omitted_unit_ids`, таблицы — в `omitted_table_ids`.
`ExpandedContext.complete` относится только к явно выбранному набору.

Таблицы выдаются один раз по идентификатору, с исходными строками и локаторами,
только при проверенном статусе и полном тексте соответствующей единицы.
Бюджет включает цитату и фактический текст каждой `UnitText`, а также JSON
заголовков и строк возвращённых таблиц. Повторяющийся текст пересекающихся
оригиналов учитывается при каждом повторении; таблицы оплачивают бюджет один раз.
Геометрия PDF и служебные метаданные не вытесняют текстовые свидетельства.

Чистая функция `expand_context` находится в `retrieval.expansion`. Загрузчик
PostgreSQL читает источник, единицы и таблицы в одной транзакции REPEATABLE READ;
embeddings и ранжирование для расширения не нужны.

`benchmark-v2.json` сохраняет прежние независимо проверенные адреса, страницы,
формулировки, отмены, роли и строки таблиц. Поиск проверяет выдержку в найденной
части; заголовок родителя не засчитывается как полный текст. Оригиналы,
примечания 16(1)/16(8), исключения 16(4) и 68-A → 68 проверяются отдельно.
В отчёте `records` и `summary` относятся к поиску, `expansion_records` — к
выбранным операциям с отдельными языком, видом операции, полнотой и цитатами.
Исторические `benchmark.json` и 108 измерений Шага 8 не переопределяются.

## Замечания в результатах поиска

`SearchResult` возвращает диагностику только для текста, вошедшего в `hits`.
Отбор происходит после ранжирования, `limit` и проверки бюджета; замечания
непоказанных кандидатов не входят в ответ. Формат существующих полей сохранён:

- `unresolved_references`, `structure_issues`, `omissions` относятся к единицам
  возвращённых частей, включая содержащиеся в них подпункты и явно переданные
  связанные единицы;
- `extraction_issues` отбираются по страницам локаторов возвращённого текста
  и таблиц. Их точность остаётся постраничной, как в исходном отчёте;
- `uncovered_unit_ids` ограничены тем же набором единиц;
- `table_issues` относятся к таблицам возвращённых единиц и к таблицам,
  указанным в их релевантных пропусках. Пропуск не засчитывается как
  фактически доставленная таблица.

Краткий адрес родителя и доступная ссылка без текста адресата не расширяют
область диагностики до всех замечаний родителя или адресата. При пустой выдаче
эти списки пустые; `reason` и `context_budget_exceeded` сохраняют прежний смысл.
Замечания самих фрагментов, их `review_status` и исходные отсылки не меняются.

Полный отчёт корпуса сохраняется в подготовленных данных: `report.json`
этапа chunk, `chunk/report.json` переносимого пакета и
`source_snapshots.reports` PostgreSQL. `evaluate` по-прежнему сохраняет полный
`corpus_issues` в отдельном отчёте оценки. Поисковый ответ его не дублирует.
Миграция и пересборка индекса для изменения выдачи не нужны.

В проверенном запросе о резидентстве глобальные 400 неразрешённых ссылок
заменены одной отсылкой пункта 16(3), который входит в top-5. Обложка и
страница 117 исключены из диагностики этого ответа. При `limit=1` возвращается
16(1), и все списки замечаний пустые. Проверка выполнена чтением рабочего
индекса с сохранённым настоящим query embedding; новых HTTP-вызовов нет.
